### Needs your decision (not fixed)

**`npm audit --audit-level=high` fails (the CI gate).** I introduced it in Phase 5
(`eslint-config-next` / `@next/eslint-plugin-next`). Verified there is no patched `braces`.
The proportionate fix is to remove both packages from `apps/website` and keep the shared ESLint
rules, adding a `no-restricted-syntax` ban on raw `<img>`. I removed them and the audit went to
0 vulnerabilities, but that requires editing `apps/website/eslint.config.js`, which a
**config-protection hook blocked**. I did not bypass it and restored the packages, so lint stays
green and the audit stays red. **Approve the `eslint.config.js` change (or disable the hook for
that one edit) and it is a two-minute fix.**

### Other findings (reported, not fixed: outside the allowed fix scope)

- `apps/website/next-env.d.ts` (generated) is not git-ignored; `e2e/playwright-report/` is not either.
- `infra/scripts/dev_certs.sh` fails on **Windows Git Bash**: `MSYS_NO_PATHCONV=1` passes `/i/...`

## 4. Database schema inventory (input for Phase 7)

Source: the live schema after `alembic upgrade head` (revision `a31a56ffc3d0`, the only
migration), read through the SQLAlchemy inspector. 10 tables. IDs are `BINARY(16)` UUIDv7.

**Headline facts**

- **No table has `public_id`.** Every external reference today uses the internal UUID.
- `tenant_id` is present on 8 of 10 tables; the two without it are global by design
  (`tenants`, `permissions`).
- `UNIQUE(tenant_id, id)` exists on **only 2 tables** (`users`, `roles`): exactly the parents
  that composite FKs currently point at.
- **Composite tenant FKs exist on 3 tables / 4 constraints** (`refresh_tokens` 1, `role_permissions`
  1, `user_roles` 2). `students`, `audit_logs` and `tenant_settings` have none, so any future table
  referencing `students` cannot get a database-level tenant guarantee until `students` gains
  `UNIQUE(tenant_id, id)`.
- Soft delete (`deleted_at`) exists on `users` and `students` only.

## 6. Top 10 risks, ranked by security impact

1. **Privileged accounts can be password-only, and there is no recovery path.** MFA is optional
   for every role including admin/principal (P2-02); no recovery codes (P2-01); no password
   reset/change/invitation endpoints (P2-05), so a compromised admin password cannot be rotated
   through the product and a forgotten one cannot be recovered. The portal's reset pages call
   endpoints that do not exist.
2. **Tenant isolation is enforced only in application code.** Host-based resolution is not
   implemented (P2-20); in the schema only `users` and `roles` can be the target of a composite
   tenant FK, and `students`, `audit_logs`, `tenant_settings` cannot. Safe today (single tenant,
   48 isolation tests pass); the moment a second tenant is enabled, one missing repository scope
   becomes a cross-tenant leak with no database backstop. **Phase 7 must close this first.**
3. **Sensitive data is plaintext at rest, and backups are unencrypted.** No field-level encryption
   (P2-11); `students` already stores date of birth in clear; only TOTP secrets are encrypted.
   `backup_mysql.sh` produces gzip + SHA-256 only, so a copied dump exposes everything.
4. **Audit trail is tamper-evident but not tamper-proof.** Append-only is enforced by the ORM; the
   application database user can still `UPDATE`/`DELETE` (grants not restricted, P2-12), and the
   chain is not anchored outside the database (P2-13). Anyone with DB write access can rewrite
   history and recompute the chain.
5. **Unauthenticated account lockout (denial of service) and a coarse rate limiter.** Five wrong
   passwords lock any known e-mail for 15 minutes regardless of source, so an attacker can keep
   the admin locked out. Limiting is a fixed window per IP with one limit for all auth endpoints
   (P2-17); schools often sit behind one NAT. (Good: auth limiters and session revocation fail
   closed when Redis is down.)
6. **Proxy-header trust is wide.** `FORWARDED_ALLOW_IPS="*"` in the API image (P2-14); nginx
   accepts any `Host` (P1-07); the website trusts `X-Real-IP`. If any service is reachable
   other than through nginx, client IPs (rate limits, audit `ip`) can be spoofed.
7. **Single JWT signing key, no `kid`, no rotation** (P2-10). Key compromise means a forced global
   re-login with no overlap window; dev uses an ephemeral key per process.
8. **Website CSP allows inline scripts** (P5-01) and the CMS is not built yet: XSS protection
   rests on the sanitiser (tested) rather than CSP. Also the default mock data source can silently
   drop enquiries in production.
9. **Session management gaps.** One global 12 h refresh TTL, no idle timeout enforced server-side,
   no concurrent-session cap, no device list/revoke/"sign out everywhere" (P2-04, P2-09); with no
   password change, revoking a stolen session is manual.
10. **Supply chain and delivery are unproven.** The CI `npm audit` gate fails today (§3); no image
    scanning/SBOM/signing (P1-11); CI has never run on a remote (P1-10); no Docker image, compose
    or full-stack E2E was executed in this audit; MinIO dev image is a community build (P1-03).
